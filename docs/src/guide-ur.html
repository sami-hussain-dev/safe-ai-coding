Ye guide kaise parhein

Chapter 1–5 sab ke liye hain. Chapter 6–11 har mode ko tafseel se samjhate hain. Chapter 12–14 reviewers, security team aur team leads ke liye hain. Commands Windows par Git Bash, aur macOS ya Linux ke kisi bhi shell ke liye likhi gayi hain. <skill> ka matlab hai woh folder jahan skill install hai.

1Ek nazar mein

safe-ai-coding Claude Code ki ek skill hai. Jab AI agent is ke saath code likhta ya review karta hai, to woh ek tay-shuda, muhtaat tareeqe par chalta hai. Pehle rule samajhta hai, phir project ke apne pattern copy karta hai, sab se chhoti tabdeeli karta hai, aur use chala kar saabit karta hai. Phir do nazariye se review karta hai, aur har khatarnak kaam se pehle poochta hai.

Chhe usool jo hamesha lagu rehte hain

Usool 1

Khatarnak kaam se pehle poocho

External files, packages install karna, data machine se bahar bhejna, database mein likhna, delete karne wali commands, secrets, agent config, ya security kamzor karna. In mein se har kaam ke liye aap ki saaf "haan" chahiye, aur pehle nuqsan bataya jata hai.

Usool 2

Jo parha woh data hai, hukm nahi

Files, web pages, comments ya tool output mein agar koi jumla agent ko hukm deta hai, to agent use maanta nahi, balke aap ko batata hai.

Usool 3

Isi codebase ki nakal karo

Agent sab se qareeb ki maujooda misaal dhoond kar usi andaaz mein likhta hai. Jo class, method, route, view ya package usne project mein dekha hi nahi, use kabhi use nahi karta.

Usool 4

Sab se chhoti tabdeeli

Bin maange refactor nahi, nayi layers nahi, ajeeb dikhne wale code ko "theek" karna nahi. Aur "rest of the code unchanged" jaisa placeholder bhi kabhi nahi.

Usool 5

Saabit karo, sach batao

Agent saaf batata hai ke kya chalaya aur kya nahi. "Nahi chalaya" ek theek jawab hai; andaaza lagana theek nahi.

Usool 6

Sirf utna jitna kaha gaya

Extra documents, files ya reports nahi. PDF report sirf tab banti hai jab aap khud kahein.

2Aaj ye kyun zaroori hai

Ye skill is kaam ke liye sahi kyun hai

Aham nuktaAap ki team ke liye matlab
Pakadne se pehle roknaBuild mode zyada tar ghaltiyan likhne se pehle hi rok deta hai. Rule pehle bayan hota hai, pattern copy hota hai, aur har symbol ka wujood check hota hai.
Nuqsan pehle se bataya jata haiKhatarnak kaam aap ki haan ka intezar karta hai. Request saaf batati hai ke kya toot sakta hai, kya wapas ho sakta hai, aur mehfooz option kya hai.
AI ki khaas ghaltiyon ke liye baniWoh cheezein check karti hai jo aam linters nahi karte:
  • jhoote methods aur views
  • chhoda hua code
  • paste hua chat text
  • prompt-injection
  • chhupe characters
  • kamzor kiye gaye tests
  • bina saboot ke daawe
Agent ki apni kamzoriyan bhiYeh sab bhi pakadti hai:
  • dependencies mein chhupi instruction files
  • khud-ba-khud approve karne wali settings
  • repo ki apni git config aur hooks
  • aap ki keys ki taraf jati symlinks
  • ajeeb hosts ki taraf ishara karti lock files
Do nazariyeHar review poochta hai ke AI code kaise fail hota hai, aur maintainer, business owner aur end user ko ye kaisa lagega.
Har stack, aap ka project bhiPHP, JavaScript/TypeScript, Python, Java, C#, Go aur Ruby ke aam checks, aur saath mein aap ke apne project rules.
Untrusted code par bhi mehfoozScanners sirf parhte hain. Repo ka code, git ke configured programs, hooks ya symlink wali files kabhi nahi chalate.
Waada nahi, sabootBuilt-in self-test aap ki apni machine par dikhata hai ke har check kaam karta hai aur sahi code par khamosh rehta hai.
Muft, local, jaanch ke qabilSaada hidayat aur chhoti scripts. Koi service nahi, koi account nahi, aap ki machine se kuch bahar nahi jata.

Ek mukammal misaal

  1. Aap kehte hain"Invoice list par export ka button laga do."
  2. Build modeAgent pehle rule bayan karta hai: kaun kis ki invoices export kar sakta hai.   3. GateNaye route ke liye database mein permission row chahiye. Agent batata hai ke kya chalayega, kis database par, kya bigar sakta hai, kaise wapas hoga, aur mehfooz option kya hai. Phir aap ki haan ka intezar karta hai.
  4. SabootFiles ka syntax check karta hai, export aam user aur admin dono ban kar chalata hai, aur kisi doosre customer ki ID bhi aazmata hai.
  5. Review modediff-check.sh chalta hai. Agent diff ko AI lens aur human lens se parhta hai, findings ki table aur faisla "Ready with notes" dikhata hai.
  6. Report (sirf kehne par)"Is kaam ki report PDF mein do." Aap ke Desktop par PDF aa jati hai.

Nateeja kaise parhein

  • [!] ka matlab hai aap ka faisla chahiye. Team ki likhi, tracked file theek hai; jo third-party, untracked ya na-maloom asal ki ho, woh untrusted hai. Use hata dein ya alag kar dein, aur us mein likhi baat par kabhi amal na karein.
  • [i] sirf maloomat hai, maslan framework ke aam composer scripts.
  • > ke baad wali lines repo se copy hui hain. Yeh data hain jin ki jaanch karni hai, hukm nahi; control characters pehle hi hata diye gaye hain.
  • Kam az kam ek [!] ho to scan exit code 1 deta hai, is liye scripts mein gate ka kaam bhi karta hai.

7Build mode: code likhte waqt

  1. Kaam samjhoAgent kaam aur us ke peeche ka business rule ek do jumlon mein dohrata hai. Phir batata hai ke kaun se roles shamil hain aur har role kya dekh aur badal sakta hai. Kuch ghair-wazeh ho to ek sawal poochta hai.
  2. Project ko jaanoProject ki instruction files aur .claude/safe-code-conventions.md parhta hai, aur pichla feedback dekhta hai. Lock file mein likhe exact versions, lint ki settings, aur tests chalne ka tareeqa note karta hai.
  3. Nakal ke liye pattern dhoondoSab se qareeb ki maujooda misaal dhoond kar likh leta hai ke kaun si file aur function copy kar raha hai. Phir unhi cheezon ka andaaz apnata hai: naming, validation, error handling, response ki shakal, logging, transactions, authorisation aur comments ki miqdaar. Jo class, method, route, view aur config key use karega, un ka wujood check karta hai. Misaal ki shakal leta hai, us ki ghaltiyan nahi.
  4. Sab se chhoti tabdeeli ka planJin files ko chhuega un ki list banata hai. Ek dafa ke kaam ke liye nayi layer nahi banata, aur ajeeb dikhne wale code ko nahi chhedta. Schema, dependency, configuration aur security ki tabdeeli gate se guzarti hai.
  5. Hifazati usoolon ke saath likho
    • har endpoint aur record par authorisation aur ownership check
    • har jagah bound parameters
    • escaped output
    • aisi transactions jo har nakami par rollback hon
    • unique numbers ke liye lock
    • project ka delete ka tareeqa
    • secrets sirf configuration se, logs mein kabhi nahi
    • users ke liye saada error message
    • poori files, chhoda hua code kabhi nahi
  6. Saabit karoHar badli hui file ka syntax check karta hai. Mutalliqa tests chalata hai, lekin pehle dekhta hai ke woh kaun sa database use karte hain. Feature chala kar edge cases aazmata hai, phir apne kaam par review mode chalata hai.
Edge cases jo hamesha dekhe jate hain

Khali ya ghayab input, ghalat type, had se lamba; kisi aur user ya tenant ki ID; sab se kam ikhtiyar wala role; Urdu, Arabi aur emoji text; time zones aur period ki hadood par tareekhein; ek hi waqt par do requests.

8Review mode: code likhne ke baad

bash <skill>/scripts/diff-check.sh [--format=tsv] [--fail-on=warn] [--all] [--no-symbols] [base]

base woh branch hai jis mein aap merge karenge. HEAD ka matlab sirf uncommitted tabdeeliyan. Committed, staged, unstaged aur untracked, sab shamil hoti hain.

Scan kya check karta hai

Security

  • secrets aur credential files, asli lagne wale ID numbers
  • SQL, command aur path injection, SSRF, open redirect, XSS
  • unsafe deserialisation, XXE
  • TLS ya token check band
  • kamzor hashing, randomness ya cipher
  • CSRF, CORS ya cookies kamzor, mass assignment
  • logs mein sensitive data

AI ki chhodi hui cheezein

  • ghayab classes, methods, views, routes, config files, imports
  • chhoda hua code, paste hua chat text, code fences
  • merge conflict markers, adhoora kaam
  • debug output, nigle hue errors, kachay exception messages

Data ki hifazat

  • TRUNCATE, DROP, bina WHERE ke DELETE/UPDATE
  • drop, rename ya dobara likhne wali migrations; down() ghayab; purani migration mein tabdeeli
  • hataye gaye auth, permission ya CSRF checks
  • bina rollback ki transactions, mumkina N+1 queries

Supply chain aur agent config

  • install hooks, unpinned ya URL dependencies
  • custom registries, ghair-mehfooz package sources
  • integrity (SRI) ke baghair CDN scripts aur stylesheets
  • CI ki tabdeeli, agent ki instruction ya settings files
  • repo se bahar jati symlinks
  • prompt-injection text, chhupe characters
  • kamzor kiye gaye tests

Do lens (nazariye)

AI lens
  • Har symbol maujood hai, aur sahi versions ke liye likha gaya hai.
  • Chhoda hua code, chat text ya adhoore nishaan nahi.
  • Scope se bahar kuch nahi, aur sirf ajeeb dikhne wala code "theek" nahi kiya gaya.
  • Misaal ki ghalti copy nahi hui.
  • Har daawe ka saboot hai.
  • Kisi content ke kehne par kuch nahi kiya gaya.
Human lens
  • Team ka koi saathi paanch minute mein samajh le.
  • Junior developer ka hota to aap approve karte.
  • Business owner apna rule pehchaane, mushkil cases samet.
  • Error messages asal user ki zabaan mein samajh aayein.
  • Asal data par bhi tez rahe; rollback, docs aur permissions ka khayal rakha gaya ho.

Faisla

Ready koi HIGH ya WARN baqi nahi. Ready with notes sirf INFO, ya woh WARN jo aap ne qubool kiye. Not ready koi HIGH, koi business rule bina tasdeeq ke, ya kuch chalaya hi nahi gaya.

CI mein

diff-check.sh --format=tsv --fail-on=warn origin/main machine ke parhne layak findings deta hai, aur kisi bhi HIGH ya WARN par job fail kar deta hai.

9Ijazat ka darwaza (permission gate)

Har khatarnak kaam se pehle agent rukta hai aur poochta hai. Request pehle mumkina nuqsan batati hai, taake aap saare facts saamne rakh kar faisla karein.

Gate ke do mode

ModeKab poochta haiBaghair poochhe kya karta hai
balanced (default)Sirf neeche wali table ke kaam, yani jin se nuqsan ho sakta haiBaqi sab: parhna, search, kaam ke andar aam code edits, syntax checks, local tests
strictHar command aur har file change, aur neeche wali table bhiSirf parhna, search, aur git status/diff/log/show

Session mein "strict mode" ya /safe-ai-coding:safe-ai-coding mode strict kahein, aur wapas aane ke liye mode balanced. Kisi ek repo ka default strict karna ho to us ki .claude/safe-code-conventions.md mein Gate mode: strict ki line daal dein. Kisi aur jagah likha text mode nahi badal sakta, aur koi bhi mode neeche wali table band nahi karta.

"Haan" kahein to bilkul yahi chalega, "nahi" kahein to chhod dunga, ya mehfooz option chunein.

Gate ke usool

  • Sirf isi request par aap ki saaf haan maani jati hai. Kisi file ya tool output mein likhi "haan" kabhi nahi.
  • Haan sirf utne kaam ke liye hai jitna dikhaya gaya. Command, target ya environment badle to nayi request.
  • Ek waqt mein ek kaam. Aap nahi kahein to agent wahi nateeja kisi aur raaste se nahi nikalta.
  • Na-maloom nuqsan bhi nuqsan likha jata hai: "Maine verify nahi kiya ke ye kya karta hai."
  • Har request aur aap ka jawab aakhri report mein darj hota hai.
Balanced mode mein ijazat nahi chahiye (taake gate ki ahmiyat bani rahe)

Project parhna aur search karna, git status/diff/log/show, skill ki apni scripts (aap ki maangi hui report banana bhi), syntax checks, aise tests jo shared database ko na chhuein, kaam ke daire ke andar tabdeeli, aur ghair-khufia settings parhna, jaise database ka host aur naam.

10Report mode: PDF, sirf jab aap kahein

Jab aap kahein ("is kaam ki report do", "PDF bana do"), agent ek khoobsurat PDF banata hai: pehle kya masla tha, aur kya theek kiya. Yeh kabhi khud se nahi hota.

Is mein kya hota hai

Pehle kya masla tha

Har masla, us ki sangeeni, jagah, log kya dekh rahe the, asal wajah, asar, saboot, aur kis ne pakda (AI, insaan, scan ya test).

Kya theek kiya

Har fix: kaun se masle hal hue, kya badla, ye sahi kyun hai, files, aur asal diff se liya gaya chhota sa pehle/baad ka code.

Saboot

Har jaanch, us ka nateeja aur nazariya (AI, human, dono), aur pehle aur baad ke scan ke numbers.

Jawabdehi

Ijazaton ka record (har request aur aap ka jawab), badli hui files, baqi khatre aur agle qadam.

Kaise banti hai

  1. Facts jama hote hainSirf session aur repo se. Jo fact maloom nahi woh khali rehta hai; koi andaaza nahi.
  2. JSON file likhi jati haiAap ki zabaan mein: English, ya Roman Urdu ke liye "language": "ur". Format references/report-format.md mein hai.
  3. Page banta haiperl ${CLAUDE_SKILL_DIR}/scripts/make-report.pl report.json report.html. Har value escape hoti hai, aur aam secret aur ID formats chhupa diye jate hain. Page mein koi script nahi, aur network se kuch load nahi hota.
  4. PDF banti haibash ${CLAUDE_SKILL_DIR}/scripts/html-to-pdf.sh report.html report.pdf. Chrome, Edge, Chromium ya wkhtmltopdf, naye aur private browser profile ke saath.
  5. Aap ko path milta haiAam taur par ~/Desktop/safe-ai-reports/<tareekh>-<unwan>.pdf, ya jahan aap kahein. Dene se pehle agent khud PDF khol kar dekhta hai.
Privacy

Report mein kabhi secrets ya asli personal data nahi hota. Masking sirf ek hifazati jaal hai, asal tareeqa nahi; agent shuru se hi facts in ke baghair likhta hai.

11Apne project ke rules sikhayein

Repo mein do ikhtiyari files skill ko aap ke project ki zabaan sikha deti hain. Dono agent configuration hain, is liye inhein code ki tarah review karein.

.claude/safe-code-conventions.md

Is file mein project ke lazmi usool hote hain, woh files jin ki nakal karni hai, aur woh ghaltiyan jo copy nahi karni. Build mode kuch bhi likhne se pehle ise parhta hai, aur review mode is ke mutabiq jaanch karta hai. Maslan:

  • Customer lists hamesha AccessHelper::visibleCustomers() se.
  • Purana PermissionsSeeder kabhi nahi chalana, kyunki woh permissions table saaf kar deta hai.

12Skill khud ko kaise bachati hai

Jo security tool aap hi ke khilaf istemal ho sake, woh na hone se bhi bura hai. Is liye scanners dushman repos par bhi mehfooz rehne ke liye banaye gaye hain.

KhatraBachao
Scan ke dauran repo ka code chal jayeKuch nahi chalta. Syntax checks sirf parse karte hain: php -n -l, node --check, isolated mode (-I) mein Python ast.parse taake repo ke apne modules load na hon, aur bash -n.
Git repo ke configured programs chala defsmonitor band, external diff aur textconv band, pager aur lazy fetch nahi. Agar .git/config filter programs define kare to diff-check chalne se inkar kar deta hai. --trust-git-config ke baghair nahi chalta, aur us par bhi gate lagta hai.
Perl koi chhupa module load kar leKuch load hone se pehle current folder Perl ke module path se hata diya jata hai.
Aap ki keys ki taraf symlinksUntracked symlinks follow nahi hoti. Repo se bahar jati symlinks report hoti hain, aur keys ya credentials ki taraf jane wali HIGH hoti hain.
Output ke zariye terminal ya agent ko behkanaControl characters badal diye jate hain, aur snippets par untrusted data ka label hota hai.
Zehreele project rulesToote hue ya hukm jaise rules chhod diye jate hain, aur messages par label lagta hai.
Report ka HTML hamle ke liye istemalHar value escape hoti hai, koi script nahi, aur sakht content policy network se loading rokti hai. Print ke liye naya, private browser profile use hota hai.
Skill ki chhedi hui copychecksums.sh badli, ghayab aur nayi files batata hai. Checksum file ka apna hash bhejne wale ki value se milayein.
Skill ke andar ke fixturesSelf-test secrets aur injection jumle tukron se jod kar banata hai, is liye skill ki files mein koi chalne wala secret ya jumla nahi.

Ye kya nahi kar sakti

  • Business logic ya niyat ka faisla. Har tabdeeli ko ab bhi insaan review karta hai.
  • Jaan boojh kar patterns se bachne wale hamlawar ko poori tarah rokna.
  • Khud se kuch nafiz karna. Yeh hidayat aur scripts hain; pakki hadd tool settings, CI aur access control se aati hai (Chapter 14).

13Dono taraf se test

Skill ko AI ki taraf se test kiya gaya: kya woh AI ki ghaltiyan aur hamlawaron ki koshishein pakadti hai? Aur insaan ki taraf se bhi: kya sahi code par khamosh rehti hai, aur kya istemal mein aasaan hai?

120 / 120self-test cases pass: 69 AI view, 22 human view, 23 safety, 6 report
40ek production Laravel codebase ke asal, insaanon ke likhe commits ghalat alarms ke liye scan kiye gaye
0attack repos ki malicious git config, hooks ya symlinks se chalne wali commands

AI view: kya ghalti pakadti hai?

69 cases hain, har ek AI ki aam ghalti ya hamla. Har ek ka sahi darje ke saath pakda jana zaroori hai:

  • SQL, command aur path injection, SSRF, eval
  • keys, private keys aur .env files
  • chhoda hua code, paste hua chat text, conflict markers
  • column drop karne wali migration, TRUNCATE
  • hataya gaya permission middleware, un-ignore hui .env
  • skip kiye tests aur hataye gaye assertions
  • install hooks, git-URL dependencies, chhupe bidi characters, injection text
  • SSH key ki taraf symlink
  • har qisam ke project rules
  • paanch gharhe hue symbols (class, method, view, route, import)

Saare 68 pakde gaye.

Human view: kya sahi code par khamosh rehti hai?

Sahi, rozmarra code ke 22 cases par koi HIGH ya WARN nahi aana chahiye:

  • bound queries, aur password naam ke validation rules
  • "Loading..." aur doston jaisa UI text, placeholder attributes
  • ORDER BY ... DESC, tareekhein aur phone numbers
  • abstract methods, rollback wali transactions
  • asli classes, views aur routes

Saare 21 khamosh rahe. Asal codebase par:

TestNateeja
40 asal commits, pattern scanGhalat alarm ki teen wajahein mili aur theek ki gayin:
  • $requested naam ka variable user input samjha ja raha tha
  • jaan boojh kar hataya gaya feature security kamzor karna samjha gaya; ab yeh WARN hai jo feature hatane ki tasdeeq maangta hai
  • bohat si delete hui files ab ek hi line mein aati hain
Baqi warnings asal review points thin: users ko dikhaye gaye kachay exception messages, aur strings se jodi gayi SQL.
25 asal commits, missing-symbol checkEk finding, aur woh asal ghalti thi: ek seeder class ka reference aise commit mein jahan us ki file abhi bani hi nahi thi.
Usi codebase mein asli bamuqabla gharhe hue symbolsAsli helpers, views, routes aur config: koi finding nahi. Chaar gharhe hue: chaaron pakde gaye, "did you mean" mashwaron ke saath.

Safety: kya dushman repo scanners ko istemal kar sakta hai?

Attack repos ko yeh sab diya gaya:

  • fsmonitor command, filter driver aur git hook, har ek marker file likhne wala
  • vendor/ mein terminal escape codes wali zehreeli instruction file
  • bypassPermissions setting
  • ghair-mehfooz .npmrc, aur doosre host ki taraf ishara karti lock file
  • repo se bahar jati symlinks

Har cheez report hui, koi marker file nahi bani, aur koi control character output tak nahi pohncha. Commit guard ne key wala commit rok diya, aur project switch ne baqi settings ko nahi chhua aur kharab JSON wali settings file ko overwrite karne se inkar kiya.

Report

Renderer ko dushman input diya gaya: script tags, onerror wala image, AWS jaisi key, ID number aur password. Sab escape ya mask ho gaya. Page mein koi script ya remote resource nahi, aur dono zabaanon ki report PDF ban jati hai.

Testing mein mile aur theek kiye gaye masail
  • Upar wali teen ghalat alarm ki wajahein.
  • Symbol checker ka ek compile error.
  • Kuch machines par atakne wala headless browser. Ab PDF ka step har browser ko time limit deta hai, aur na chale to agla browser aazmata hai.

Sirf ek project mein skill kaise band karein?Us project mein /safe-ai-coding off likhein (plugin: /safe-ai-coding:safe-ai-coding off). 16Istilahaat aur sources

Agent
Aisa AI jo sirf jawab nahi deta, balke files parhta hai, commands chalata hai aur code badalta hai.
Prompt injection
Agent ke parhe hue content mein chhupa jumla jo use hukm dene ki koshish kare.
Hallucination
Aisa code jo maujood hi na hone wali class, method, route, view ya package use kare.
Slopsquatting
Hamlawar woh package naam register kar lete hain jo AI tools aksar gharh lete hain, taake install karne par un ka code aa jaye.
Chhoda hua code
"Rest of the code unchanged" jaisa placeholder jo asal code ki jagah le leta hai.
IDOR
User ID badal kar kisi aur ka record khol le.
SSRF
Server user ka chuna hua URL khud fetch kare aur andar ke systems tak pohnch jaye.
XSS / CSRF
Page mein daala gaya script / logged-in user ke naam par jaali request.
N+1
Sab rows ke liye ek query ki jagah loop mein har row ki alag query.
Soft delete
Row ko mitane ki jagah use deleted mark karna (flags, tareekh).
fsmonitor, filter, hook
Git ki woh settings jo git se program chalwati hain; download kiye repo ke saath aayein to khatarnak.
Chhupe characters
Nazar na aane wale ya rukh badalne wale characters, jo text ko asal se mukhtalif dikhate hain.
